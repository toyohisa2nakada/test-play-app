# 遊びの成分分析（ゲームメディア論 第2回・模擬授業用）

Vite + TypeScript + React + Tailwind CSS v4 + PeerJS。サーバ不要（PeerJSの公開シグナリングサーバのみ使用）。

## 画面
| URL | 役割 |
|---|---|
| `/?host=<room>`（または `/`） | 教員PC：左に集計、右に実際に接続するスマホ画面（iframe） |
| `/?join=<room>` | 学生スマホ：回答して送信（QRコードの飛び先） |

`<room>` はホストの Peer ID。既定値は `.env` の `VITE_ROOM_ID`（配布資料のQRに使うので固定）。

## 使い方
```bash
npm install
cp .env.example .env      # 必要ならルームIDを変更
npm run dev               # LAN内のスマホからも開ける（--host）
npm run build             # dist/ を GitHub Pages 等に置けば本番URLになる
```
- **種明かし**：ラベルを日常語 → カイヨワの用語に切り替え。接続中のスマホ側の表示も同時に切り替わる。
- **架空の44人**：シード固定の架空データ（`src/dummy.ts`）。
- **リセット**：実回答を消去（実回答はPCのlocalStorageに保存され、再読み込みしても残る）。
- 同じスマホから再送信すると上書き（1人1票）。

## 内容の編集
文言・選択肢は `src/content.ts` に集約。遊び度 = 6条件（はい1 / どちらとも0.5 / いいえ0）の平均×100（`src/model.ts`）。

## 注意
- 教員PCのタブは1つだけ開く（同じルームIDを2つのタブで取ると、後から開いた方が「解放待ち」になる）。
- 会場ネットワークがWebRTCを遮断している場合に備え、スマホ画面の埋め込みだけで操作・説明できるようにしてある。
